# תרגול חובשים • מד"א — הוראות פרסום ועדכון

**גרסה נוכחית: v13** (`CACHE_VERSION` ב-`sw.js`). בכל עדכון תוכן עתידי יש להעלות את המספר הזה (ראו "איך לעדכן קובץ" למטה) — הוא לא צריך להישאר מסונכרן עם המספר הזה במסמך; המקור האמיתי הוא תמיד מה שכתוב בפועל ב-`sw.js`.

אפליקציית תרגול שאלות שרצה לגמרי בדפדפן, ללא שרת אחורי. אפשר להתקין אותה כ-PWA (אייקון על המסך הראשי, עובדת אופליין).

## אילו קבצים להעלות ל-GitHub

**רק תשעת הקבצים האלה** (לא ה-PDF, לא קבצי המקור הגולמיים, ולא שני קבצי הפרומפט — אלה שימשו רק בזמן הכנת התוכן, ולא נטענים בזמן ריצה):

```
index.html
manifest.json
sw.js
question_bank.js
generated_content.js
icons/icon-192.png
icons/icon-192-maskable.png
icons/icon-512.png
icons/icon-512-maskable.png
```

חשוב לשמור את מבנה התיקיות בדיוק כך — תיקיית `icons` עם ארבעת הקבצים בתוכה, ושאר חמשת הקבצים ברמה הראשית (root) של הריפו. `index.html` מפנה לקבצים האחרים בנתיבים יחסיים, אז אם המבנה משתנה האפליקציה תישבר.

**קבצים שנשארים מחוץ לריפו, לשימוש עבודה בלבד:**
- `processing_prompt.md` — פרומפט להמרת קובץ שאלות גולמי (עם תשובות) לפורמט `question_bank.js`.
- `generation_prompt.md` — פרומפט ליצירת שאלות חדשות מתוך תמצית ידע, לפורמט `generated_content.js`.
- כל קובץ preview ביניים (למשל `preview_matching_grouping.html`) ששימש לאישור UI לפני שילוב — כלי עבודה, לא חלק מהאפליקציה.

## איך לפרסם עם GitHub Pages (חד-פעמי)

1. צרו ריפו חדש ב-GitHub (אפשר Public או Private — Pages עובד בשניהם, אך בריפו Private נדרש חשבון עם תוכנית שתומכת בכך).
2. העלו את תשעת הקבצים לפי המבנה שלמעלה (גרירה בממשק הווב של GitHub, או `git push` אם נוח לכם).
3. בריפו: **Settings → Pages**.
4. תחת "Build and deployment" → Source: **Deploy from a branch**. בחרו את הענף (בד"כ `main`) ואת התיקייה `/ (root)`.
5. שמרו. אחרי דקה-שתיים GitHub ייתן לינק בסגנון `https://USERNAME.REPO-NAME.github.io/`.
6. פתחו את הלינק. בנייד: תפריט הדפדפן → "הוסף למסך הבית" / "התקן אפליקציה". בדסקטופ (Chrome/Edge): סמל התקנה בשורת הכתובת.

לאחר ההתקנה הראשונית עם אינטרנט, האפליקציה שמורה במכשיר ותעבוד גם ללא אינטרנט בכלל.

## איך לעדכן קובץ (למשל להוסיף/לתקן שאלות)

1. **מחקו את הקובץ הישן בריפו והעלו את הגרסה החדשה** (או פשוט "עדכון" רגיל של הקובץ — לא צריך למחוק קודם, ב-GitHub זה אותו דבר: commit חדש מחליף את התוכן).
2. **תמיד עדכנו את `sw.js` יחד עם כל שינוי תוכן** — זה הצעד הכי חשוב שקל לשכוח. בשורה הראשונה של `sw.js` יש:
   ```js
   const CACHE_VERSION = 'v13';
   ```
   העלו את המספר ב-1 (למשל ל-`'v14'`) בכל פעם שאתם משנים תוכן כלשהו (`question_bank.js`, `generated_content.js`, `index.html`, אייקונים וכו'). זה מה שגורם למכשירים שכבר התקינו את האפליקציה לזרוק את הגרסה הישנה השמורה במטמון ולמשוך את החדשה. **בלי זה, משתמשים שכבר התקינו עלולים להמשיך לראות תוכן ישן** גם אחרי שעדכנתם ב-GitHub.
3. תנו למכשירים דקה-שתיים עם אינטרנט פתוח (בפעם הבאה שהאפליקציה נפתחת) כדי שהעדכון ירד ברקע.

### עדכון תוכן השאלות עצמו

`question_bank.js` הוא קובץ JSON גדול בתוך משתנה JS (`window.QUESTION_BANK = [...]`), שורה אחת ארוכה של מאות שאלות. **לא מומלץ לערוך אותו ידנית בעורך טקסט רגיל** — טעות קטנה בפסיק או במרכאות שוברת את כל הקובץ (ואת האפליקציה כולה, כי היא נטענת כ-script אחד).

הדרך הבטוחה, ולפי סוג העדכון:

- **הוספת/תיקון שאלות מקובץ שאלות-עם-תשובות קיים** (למשל קובץ Word עם שאלות אג"מ): להעלות אותו יחד עם `processing_prompt.md` לשיחה עם Claude. הפרומפט ממיר לפורמט הנכון, כולל זיהוי אוטומטי של סוג השאלה (רגילה / רב-בחירה / שידוך / קיבוץ / מילוי-טבלה) וסיווג `qtype`. התוצר נמסר כקובץ preview נפרד לבדיקה — לא משולב אוטומטית ל-`question_bank.js` הראשי.
- **יצירת שאלות חדשות מתוך חומר לימוד** (לא שאלון קיים, אלא למשל תמצית ידע/מצגת): להעלות אותו יחד עם `generation_prompt.md` וגם עם `generated_content.js` הקיים. התוצר הוא קובץ `generated_content.js` שלם, מוכן להחלפה ישירה.
- בשני המקרים: לבקש מ-Claude לוודא שהקובץ תקין (JSON valid + כל השאלות עדיין נטענות) לפני שמעלים אותו.

## סוגי שאלה נתמכים

חמישה סוגים, מאורגנים כשני זוגות ועוד אחד:

| סוג | שדה מזהה | תיאור |
|---|---|---|
| **רגילה** | (אין `type`, `multi: false`) | תשובה אחת נכונה מתוך `options` |
| **רב-בחירה** | (אין `type`, `multi: true`) | כמה תשובות נכונות יחד מתוך `options` |
| **שידוך** | `type: "match"` | זיווג 1:1 בין שתי רשימות שוות-גודל (`col1`/`col2`/`correct`) |
| **קיבוץ** | `type: "group"` | מיון פריטים לקטגוריות (`categories`/`items`/`correct`) |
| **מילוי טבלה** | `type: "table-fill"` | שיבוץ ערכים לתאים בטבלה דו-ממדית — "הבן-דוד" של קיבוץ (`rows`/`cols`/`cells`) |

שדה `qtype` (מערך: `concept`/`numeric`/`scenario`) חל על כל חמשת הסוגים, בלתי-תלוי בהם.

בשידוך/קיבוץ/מילוי-טבלה, סדר התצוגה (איזה פריט מופיע באיזו שורה) מתערבב מחדש בכל טעינה — הנכונות עצמה תמיד לפי מפתח, לא מיקום, כך שזה לא משפיע על הבדיקה, רק מונע תבנית קבועה לשינון.

## מבנה קובץ שאלה (לעיון)

### רגילה / רב-בחירה
```json
{
  "id": "bank_0042",
  "section": "טראומה",
  "qtype": ["concept"],
  "question": "טקסט השאלה...",
  "multi": false,
  "options": {"א": "...", "ב": "...", "ג": "...", "ד": "..."},
  "correct": "ג",
  "note": null,
  "explanation": {"correct": "...", "wrong": "..."},
  "source": "generated"
}
```
- `multi: true` הופך `correct` למערך אותיות (`["א","ג"]`) במקום מחרוזת יחידה.
- `note`: הערה אופציונלית שמוצגת למשתמש (למשל עדכון פרוטוקול). `null` אם אין.
- `explanation`: חובה — הסבר לתשובה הנכונה והסבר לשגויות.
- `source`: קיים רק בשאלות שנוצרו (`"generated"`); בשאלות מהבנק המקורי השדה פשוט לא קיים.

### שידוך
```json
{
  "id": "bank_0332", "section": "אג\"מ ונהלים", "qtype": ["concept"], "type": "match",
  "question": "...",
  "col1": {"1": "...", "2": "...", "3": "..."},
  "col2": {"א": "...", "ב": "...", "ג": "..."},
  "correct": {"1": "ב", "2": "א", "3": "ג"},
  "note": null,
  "explanation": {"correct": "", "wrong": ""}
}
```

### קיבוץ
```json
{
  "id": "bank_0333", "section": "אג\"מ ונהלים", "qtype": ["concept"], "type": "group",
  "question": "...",
  "categories": {"1": "...", "2": "..."},
  "items": {"א": "...", "ב": "...", "ג": "...", "ד": "..."},
  "correct": {"א": "1", "ב": "2", "ג": "1", "ד": "2"},
  "note": null,
  "explanation": {"correct": "", "wrong": ""}
}
```

### מילוי טבלה
```json
{
  "id": "bank_0334", "section": "אנטומיה ופיזיולוגיה", "qtype": ["numeric"], "type": "table-fill",
  "question": "...",
  "rows": {"1": "נשימה (לדקה)", "2": "דופק (לדקה)"},
  "cols": {"1": "יילוד", "2": "תינוק"},
  "cells": {"1": {"1": "40-60", "2": "20-30"}, "2": {"1": "100-160", "2": "110-170"}},
  "note": null,
  "explanation": {"correct": "", "wrong": ""}
}
```
אין שדה `correct` נפרד — `cells` הוא גם התוכן וגם התשובה הנכונה.

**בשלושת הסוגים החדשים** אין שדה `multi` בכלל (לא רלוונטי מבנית), ו-`explanation.correct` ריק כברירת מחדל — בניגוד לשאלה רגילה, כי הטבלה/הזיווג המלא כבר גלויים למשתמש בשלב החשיפה. `explanation.wrong` תמיד ריק בהם. פירוט מלא של כל הכללים והולידציה נמצא ב-`processing_prompt.md`.

## בעיות נפוצות

- **האפליקציה לא מתעדכנת אחרי שינוי**: כמעט תמיד כי שכחתם להעלות את `CACHE_VERSION` ב-`sw.js`.
- **מסך ריק / שגיאה בקונסול**: כנראה JSON לא תקין ב-`question_bank.js` או `generated_content.js` אחרי עריכה ידנית — בדקו עם בודק JSON (JSONLint או דומה) לפני העלאה.
- **שאלה חדשה לא מופיעה בכלל**: בדקו ש-`section` תואם בדיוק אחת המחרוזות ב-`PRIORITY_ORDER` בתוך `index.html` (או שהיא תישאר "לא מדורגת" — עדיין תוצג, רק לא בעדיפות מכוונת). נושא חדש לגמרי (כמו שנעשה עם "אג\"מ ונהלים") דורש הוספה מפורשת לרשימה הזו.
- **שאלת שידוך/קיבוץ/מילוי-טבלה נראית שבורה או לא ניתנת לבדיקה**: כנראה `correct` לא תקין — בשידוך זה חייב bijection מלא (כל מפתח בכל צד בשימוש פעם אחת בדיוק), בקיבוץ כל פריט חייב מפתח קטגוריה תקין, במילוי-טבלה כל שורה ב-`cells` חייבת ערך לכל עמודה.
- **האייקון לא מתעדכן על המסך הראשי**: אייקונים גם הם ב-cache; מחקו את ההתקנה הישנה מהמכשיר והתקינו מחדש אחרי עדכון גרסה.
