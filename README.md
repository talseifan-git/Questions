# תרגול חובשים • מד"א — הוראות פרסום ועדכון

**גרסה נוכחית: v1** (`CACHE_VERSION` ב-`sw.js`). זו נקודת ההתחלה — בכל עדכון תוכן עתידי יש להעלות את המספר הזה (ראו "איך לעדכן קובץ" למטה).

אפליקציית תרגול שאלות שרצה לגמרי בדפדפן, ללא שרת אחורי. אפשר להתקין אותה כ-PWA (אייקון על המסך הראשי, עובדת אופליין).

## אילו קבצים להעלות ל-GitHub

**רק תשעת הקבצים האלה** (לא ה-PDF ולא קובץ ה-MD של תמצית הידע — אלה שימשו רק בזמן הכנת התוכן, ולא נטענים בזמן ריצה):

חשוב לשמור את מבנה התיקיות בדיוק כך — תיקיית `icons` עם ארבעת הקבצים בתוכה, ושאר חמשת הקבצים ברמה הראשית (root) של הריפו. `index.html` מפנה לקבצים האחרים בנתיבים יחסיים, אז אם המבנה משתנה האפליקציה תישבר.

## איך לפרסם עם GitHub Pages (חד-פעמי)

1. צרו ריפו חדש ב-GitHub (אפשר Public או Private — Pages עובד בשניהם, אך בריפו Private נדרש חשבון עם תוכנית שתומכת בכך).
2. העלו את תשעת הקבצים לפי המבנה שלמעלה (גרירה בממשק הווב של GitHub, או `git push` אם נוח לכם).
3. בריפו: **Settings → Pages**.
4. תחת "Build and deployment" → Source: **Deploy from a branch**. בחרו את הענף (בד"כ `main`) ואת התיקייה `/ (root)`.
5. שמרו. אחרי דקה-שתיים GitHub ייתן לינק בסגנון `https://USERNAME.REPO-NAME.github.io/`.
6. פתחו את הלינק. בנייד: תפריט הדפדפן → "הוסף למסך הבית" / "התקן אפליקציה". בדסקטופ (Chrome/Edge): סמל התקנה בשורת הכתובת.

לאחר ההתקנה הראשונית עם אינטרנט, האפליקציה שמורה במכשיר ותעבוד גם ללא אינטרנט בכלל.

## איך לעדכן קובץ (למשל להוסיף/לתקן שאלות)

1. **מחקו את הקובץ הישן בריפו והעלו את הגרסה החדשה** (או פשוט "עדכון" רגיל של הקובץ — לא צריך למחוק קודם, ב-GitHub זה אותו דבר: commit חדש מחליף את התוכן).
2. **תמיד עדכנו את `sw.js` יחד עם כל שינוי תוכן** — זה הצעד הכי חשוב שקל לשכוח. בשורה הראשונה של `sw.js` יש:
   ```js
   const CACHE_VERSION = 'v1';
   ```
   העלו את המספר ב-1 (למשל ל-`'v2'`) בכל פעם שאתם משנים תוכן כלשהו (`question_bank.js`, `generated_content.js`, `index.html`, אייקונים וכו'). זה מה שגורם למכשירים שכבר התקינו את האפליקציה לזרוק את הגרסה הישנה השמורה במטמון ולמשוך את החדשה. **בלי זה, משתמשים שכבר התקינו עלולים להמשיך לראות תוכן ישן** גם אחרי שעדכנתם ב-GitHub.
3. תנו למכשירים דקה-שתיים עם אינטרנט פתוח (בפעם הבאה שהאפליקציה נפתחת) כדי שהעדכון ירד ברקע.

### עדכון תוכן השאלות עצמו

`question_bank.js` הוא קובץ JSON גדול בתוך משתנה JS (`window.QUESTION_BANK = [...]`), שורה אחת ארוכה של כ-680 שאלות. **לא מומלץ לערוך אותו ידנית בעורך טקסט רגיל** — טעות קטנה בפסיק או במרכאות שוברת את כל הקובץ (ואת האפליקציה כולה, כי היא נטענת כ-script אחד).

הדרך הבטוחה: לבקש מ-Claude לבצע את השינוי (הוספת שאלה, תיקון תשובה, וכו') ולתת לו לערוך את הקובץ ולוודא שהוא תקין (JSON valid + כל השאלות עדיין נטענות) לפני שמעלים אותו.

## מבנה קובץ שאלה (לעיון)

```json
{
  "id": "bank_0042",
  "section": "טראומה",
  "question": "טקסט השאלה...",
  "options": {"א": "...", "ב": "...", "ג": "...", "ד": "..."},
  "correct": "ג",
  "note": null,
  "explanation": {"correct": "...", "wrong": "..."},
  "source": "generated"
}
```
- `note`: הערה אופציונלית שמוצגת למשתמש (למשל עדכון פרוטוקול). `null` אם אין.
- `explanation`: חובה לכל שאלה — הסבר לתשובה הנכונה והסבר לשגויות.
- `source`: קיים רק בשאלות שנוצרו מהמצגת (`"generated"`); בשאלות מהבנק המקורי השדה הזה פשוט לא קיים באובייקט.

## בעיות נפוצות

- **האפליקציה לא מתעדכנת אחרי שינוי**: כמעט תמיד כי שכחתם להעלות את `CACHE_VERSION` ב-`sw.js`.
- **מסך ריק / שגיאה בקונסול**: כנראה JSON לא תקין ב-`question_bank.js` או `generated_content.js` אחרי עריכה ידנית — בדקו עם בודק JSON (JSONLint או דומה) לפני העלאה.
- **האייקון לא מתעדכן על המסך הראשי**: אייקונים גם הם ב-cache; מחקו את ההתקנה הישנה מהמכשיר והתקינו מחדש אחרי עדכון גרסה.
